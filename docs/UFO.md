# UFO（Issue #79）

## 根拠と採用した規則

[Issue #79](https://github.com/urahimono/Unity_Invader/issues/79)、[Notion 実仕様確認04](https://app.notion.com/p/3ff4f337d5bf81229a72dbcfd995f070)、[ROM逆アセンブル](https://computerarcheology.com/Arcade/SpaceInvaders/Code.html)を参照します。Notionの参考動画では約5:51に右から来たUFOを撃破して50点です。今回その動画自体の再計測はしていません。

- `0913〜092D`：編隊基準高さが第1Wave初期高さよりPlayer側へ下がってからカウンタを進めます。0を検出すると`0x0600`へ戻して開始待ちにし、そのtickでも1減らします。初期値もROM mirror `1B91〜1B92`の`0x0600`を使います。
- `0682〜06A8`：UFOはSquigglyとphase 2を共有します。開始待ちでもSquiggly飛行中はその弾を進め、空いた時に生存8体以上ならUFOを開始します。UFO中はSquigglyを新規発射せず、Rolling/Plungerは従来どおり動きます。7体以下ではUFOを開始せず、Squiggly処理を続けます。
- `0462〜0474`：通常自機弾終了回数が奇数なら左→右、偶数なら右→左です。UFO出現ごとに交互にするものではありません。飛行開始時に決めた方向は途中の射撃で反転しません。
- `06BA〜06D2`：処理stepごとに約2px横移動し、左右の境界で解除します。

## 通常射撃終了履歴と得点

GameplayDriverの`_normalShotEndCount`を唯一の履歴として保持し、方向は偶奇、得点表位置は`count % 15`から導出します。表位置や方向用カウンタを別に複製しません。初期履歴は0で、ROM mirrorの得点ポインタ`1D54`先頭に対応します。

PlayerShotは自然終了のFlightEndedを通知し、UFO命中なら続けてUfoDefeatedを通知します。Issue #85からDriverが通常弾を明示的に参照し、履歴・加点処理を直接購読します。Invader命中、Shield吸収、画面上端、UFO命中で履歴が1回進み、発射、穴通過、Pause、Player死亡後の強制回収、デバッグ弾の回収では進みません。B絨毯爆撃は同じPrefabを使用し、UFO通知だけ購読して通常履歴から除外します。B弾もUFOを撃破して現在の表位置の得点を得られます。弾自身は通知先や通常弾かどうかを知りません。

使用する先頭15値（点）は次のとおりです。ROM `1D54〜1D63`には16値ありますが、`044C〜0451`のwrapで16番目の50は通常使用しません。

`100, 50, 50, 100, 150, 100, 100, 50, 300, 100, 100, 100, 50, 150, 100`

ROMではUFO命中を`1579〜157E`でフラグ化し、自機弾の終了処理`0436〜045A`で表が進み、その後のUFO処理`070C〜0714`で表を読みます。本実装は爆発待ちを省略し、**UFOの命中成立→当たったPlayerShotの自然終了→進んだ表で即加点**の順です。通常弾なら、終了前の履歴0で撃破すると終了後1の50点、履歴7で撃破すると終了後8の300点です。B弾は履歴を動かさないので、履歴0なら100点です。

Ufoは自身の有効状態・Colliderで一度だけ被弾を受理し、直ちに解除します。PlayerShotも自身を消費して後続Triggerを拒否します。加点はGameplayDriverだけが行い、UFOはInvader生存数・WaveClearに関与しません。加点後、次の敵弾試行から既存のScore依存Reloadへ反映されます。Editor/Development BuildのDebugStatusOverlayへScoreを1行追加しました。

## 時間・座標・状態のUnity近似

- 出現カウンタはFormationの既存60Hz仮想tickで進めます。`0x0600`は約25.6秒相当ですが、0判定tickと次のphase 2までの待ちを含み、原作ビーム別ISR・実秒・動画テンポとの一致は未確認です。ゲーム開始直後から秒数タイマーを回す実装ではありません。
- 下降条件は現在のFormation基準（上段中心が論理y=208）からの相対下降に対応付けています。ROMの`refAlienYr < 0x78`を現行編隊座標へ写した近似であり、基準個体の絶対座標がROMと同じという意味ではありません。
- UFO移動はphase 2、3tickに1stepで2px、平均40px/秒相当です。Physics2Dは従来の0.02秒刻みとMovePositionを使用します。F倍率は編隊移動だけで、UFOカウンタ・移動・Player・待機時間・グローバル時間を変えません。ただしFで編隊が早く下降すれば、カウンタ開始条件には早く到達します。
- レーン中心y=232、当たり判定24×8px、出現中心x=-12/236、反対側へ全体が抜ける境界で解除します。ROMの`29/E0`等の座標をそのまま転用せず、現224×256画面の外から入って外へ出るよう配置した暫定値です。SpriteはEditorコードで自作した赤い簡易機体です。抽出素材は追加しません。
- 非Playing/Formation無効時は表示・Collider・物理・カウンタを停止し、位置・占有を保持します。復帰処理では残留UFO・開始待ちを解除し、カウンタを`0x0600`へ戻します。この死亡復帰時のタイマー再設定は既存の残留敵弾整理に合わせたUnity側の安全な近似で、ROMの1P継続と厳密一致とは扱いません。
- 通常終了履歴は1P死亡復帰では保持し、次Waveでは0へ戻します。ROMの1P継続`032C〜032F`とWave再初期化`09FD`→`01E4`のmirrorコピーを根拠とします。現実装がWaveで既存の自機弾を保持する点は従来仕様のままで、その弾が次Waveで自然終了すれば新Waveの履歴を進めます。

## 残る差分・対象外

UFO爆発・得点表示待ち・SEの厳密再現は対象外です。撃破で即解除するためSquiggly再開と加点時刻は原作より早くなり、爆発待ち中の追加射撃による表進行も再現しません。開始待ちフラグは出現成立時に消費します。ROMではUFO完了時に構造を再初期化する点とも異なります。

ROM mirrorの初期UFO descriptorは左側から右向きですが、本実装は初回も現在履歴の偶奇を適用し、履歴0なら右側から開始します。またROMがUFO飛行中の終了では方向descriptorを更新しない細部に対し、本実装は次回出現時に最新履歴から方向を決めます。初期方向・実秒・レーン・輪郭・境界・死亡/Wave持越しの視覚照合は未完了です。

追加残機・HighScore・原作HUD・弾相殺・侵攻敗北・2Pは追加していません。実画面・実キー・参考動画との再照合・Development Build/製品ビルドは未確認です。

## アセットと限定検証

保存済みBootstrapから起動します。`Ufo.prefab`・自作`Ufo.png`・Arcade参照はEditor APIで保存し、再設定は **Unity Invader > Configure UFO** です。再実行で重複生成せず、全体移行メニューにも同じ設定を接続しています。

Unity 6000.6.4f1の隔離コピー・非表示バッチでコンパイル・保存・限定Playが成功しました。出現条件、8/7体、共有枠の待機/占有/再開、両方向横断、通常弾16回の実UFO Triggerによる15周期と4得点・命中終了後の選択・重複抑止、Invader/Shield/上端/強制回収の履歴、UFO加点後のReload、死亡復帰・GameOver・B/F・Waveを確認しました。実Bプール弾のUFO撃破でも加点し、通常履歴が変わらないことを確認しています。

死亡復帰では検証側だけで既存の待機を進めて解除直後を観測し、B/FのWave確認中だけ追加死亡を避けるためPlayer Colliderを無効化しました。製品への検証用APIや待機・被弾処理変更はありません。詳細はPR本文、一時コードとログはGit対象外のリポジトリ直下`Logs/`に保存しています。
