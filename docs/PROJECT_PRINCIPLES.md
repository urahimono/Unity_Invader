# プロジェクトの設計原則

この文書は長期間維持する判断基準の正本です。現在の実装構造は [ARCHITECTURE.md](ARCHITECTURE.md)、重要な判断の理由は [ADR](adr/README.md)、作業手順は [AGENTS.md](../AGENTS.md) を参照してください。

## 再現の目的と根拠

- Space Invadersの挙動再現を目的とし、独自ゲーム化を優先しません。
- 原作仕様と、Unityで動かすための実装都合を分けます。開発用の近道や暫定値を原作仕様として扱いません。
- 参考プレイ動画などの根拠に基づいて仕様を確認します。不明な原作仕様を推測で確定せず、参考動画が未指定なら確認します。
- 検証済みの事実・暫定仕様・未確認事項を区別して記録します。論理検証と実際の描画・操作確認も区別します。

## ゲームルールの基準

- ゲームルールは可能な範囲で通常のC#に置き、Unity APIから独立させます。
- Unity Transform・Renderer・表示オブジェクトをゲームルールの正としません。表示は論理状態からの出力です。
- 原作相当の論理ピクセル座標を位置・寸法・当たり判定の基準とし、Unityの表示座標や拡大率と分けます。
- ゲームルールは描画FPSから分離した論理tickで進めます。表示フレーム数によってゲーム速度を変えません。

## 必要最小限の設計と共有

- Space Invaders専用の必要最小限の設計を優先します。将来用途だけを理由に汎用フレームワークや抽象化を追加しません。
- ChatやNotionは検討・議論に使い、実装上確定した原則・現在構造・重要判断はリポジトリで版管理します。特定のAI製品や過去会話がなくても参照できる状態を保ちます。
- 元ゲームから抽出した画像・音声・動画など、著作権上問題のある素材をリポジトリへ追加しません。
